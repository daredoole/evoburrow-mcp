# Contributing

Issues and pull requests are welcome. Keep changes focused, preserve the read-first safety model, and add deterministic tests for every new parser, protocol command, plan, or artifact format.

Run `npm ci`, `npm test`, `npm run validate:release`, and `npm run security:verify` before submitting. Never commit personal measurements, AVR snapshots, IP addresses, room coordinates, generated backups, or A1 binaries.

Claims about audio behavior need a source and an explicit evidence label. Community experience is useful, but it must not be presented as universal measurement science or official product behavior.
